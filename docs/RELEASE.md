# CrunchyRoll Censoring release verification

## Reproduce

Use Node 24, npm 11, and the committed lockfile. `npm ci`; `npx playwright install chromium`; `npm run release`. The cloud image has its browser binaries in `/workspace/.cache/ms-playwright`, so the executed release command is `PLAYWRIGHT_BROWSERS_PATH=/workspace/.cache/ms-playwright npm run release`.

The Browser plugin is not available. Shared Chrome/CUA startup was attempted: tab creation failed with “Browser Use could not read requirements”, and native Sky input failed because the Chrome AT-SPI provider was unavailable. The repository's regular Playwright workflow is used instead. It loads the actual unpacked bundle in Chromium; `chrome.*` APIs are not mocked and test-only host access is not added to the release manifest.

## Scope of evidence

Fixtures intercept HTTPS responses on the narrowly permitted Crunchyroll origins. They supply synthetic ASS/WebVTT, episode language metadata and a small simulation of the documented SubtitlesOctopus API. A real media element plays a generated local tone to exercise actual mute control and seeking. The fake renderer is **not** Crunchyroll or a real libass canvas. These fixtures are never used by production code or packaged.

The browser checks cover English CC, Japanese audio with English subtitles, ignored multiple matches in a cue, Unignore, timestamp seeking without reload, disable/restore, reveal masking, settings and exception persistence through browser restart, clearing exceptions, keyboard focus, narrow layout, unsupported/non-English paths, missing CC, unknown audio, captions off, a fullscreen container, source-reset ads, separate tabs, stale actions and cross-origin frame replacement. The pure tests additionally exercise literal matching, parser preservation, interval merging, replay, seeking, buffering/pausing, playback rates and manual mute ownership.

## Release assets

`dist/` is the unpacked extension. `artifacts/crunchyroll-censoring-0.1.4.zip` contains only the production manifest, HTML/CSS, locally bundled JavaScript, and icons, with `manifest.json` at its root. A SHA-256 sidecar is generated. `scripts/validate.mjs` enforces MV3, the reviewed permission inventory, restrictive CSP, local executable resources and no eval/remote imports. Production source and assets, not `dist/`, are edited.

Passing this gate packages an integration preview. It does not close missing-caption coverage, prove current Crunchyroll selectors/contracts, establish actual canvas output, cover same-source ads, or verify an actual toolbar click in Google Chrome. No store publication is authorized or performed.

## 0.1.9 manual episode timing correction

**Investigation addendum:** the reported 2:30 → 2:50 and 8:52 → 9:12 examples compare source times with the player UI, not the native media clock. A shared +20 audio/seek correction is not established; see [clock investigation](TIMING-INVESTIGATION.md). Version 0.1.9 shifts loaded matching English-dub CC audio intervals and popup navigation by a user-entered, episode-local offset. It does not estimate word timings or mute reactively from a newly displayed subtitle. Automatic clock mapping and universal dub coverage remain unmet.

Focused live checklist (requires authorized Crunchyroll access):

1. Update the existing installation folder, Reload the extension, refresh the episode, and select English audio with matching English [CC]. Confirm version 0.1.9 and both coverage statuses.
2. First confirm that the native media clock equals the player UI and that matching CC cue onsets are consistently +20 later on that native clock. If those checks fail, stop this manual-offset test and investigate the separate mappings. Only with those checks satisfied, enter **20** in **Timing correction (this episode)**, then **Apply correction**. The supplied CC timestamps should change from 2:30 and 8:52 to 2:50 and 9:12. Seek, play through each, and verify muting starts before the speech and ends after its full cue. It can silence surrounding dialogue.
3. Ignore one match, then Unignore it. In a multi-match cue, one ignored match must not unmute other enabled matches. Check subtitles restore from the original text and that playback resumes after timestamp seeking.
4. With loaded CC still available, turn visible subtitles off and replay a corrected interval. Confirm audio still filters. Test pauses, seek/replay and playback-rate changes; manual mute and volume must remain yours.
5. Close/reopen the popup: +20 should remain. Start another tab: correction should be zero. Let autoplay advance or reload: correction must reset. Verify the next episode independently; do not assume +20 applies to it. Japanese audio stays untouched.
6. Check fullscreen and English versus English [CC]. A sustained observed cue mismatch should show **Audio filtering unavailable**, disable that track's links and leave supported text filtering working. A changing offset or missing/mismatched CC remains unsupported. The mismatch guard cannot verify all timing, particularly with subtitles hidden.
