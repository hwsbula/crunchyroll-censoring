# CrunchyRoll Censoring architecture

## Boundaries

- `src/core/settings.ts`: versioned settings schema, explicit starter terms, literal normalization, limits and SHA-256 identities.
- `src/core/matcher.ts`: pure matcher; original UTF-16 offsets survive normalization. Longest non-overlapping phrases take precedence. Never executes user patterns.
- `src/core/captions.ts`: local ASS/WebVTT parsing. Retains originals, cue timestamps and source-to-visible-text maps. ASS document redaction preserves override tags, positioning, timing, punctuation and line breaks. Both formats also supply original cue text/matches to the guarded Bitmovin DOM adapter; WebVTT documents are not rewritten on the network.
- `src/core/engine.ts`: language/coverage policy, occurrence analysis, exceptions, renderer updates and bounded session logs.
- `src/core/seeker.ts`: bounded asynchronous seek completion and cancellation when the episode/player changes. Preserves host playback intent and acknowledges the popup only after the media has reached the requested time.
- `src/integration/seek.ts`: document-start interception of the standard Media Session `seekto` registration, forwarding registration unchanged. Calls the captured player-owned handler only for its bound media element; respects removal/rejection without a native retry. No private player object search or synthetic SDK events.
- `src/core/scheduler.ts`: merged media-time intervals and a per-element `muted` accessor gate. Records outside writes, including same-value manual mute intent, independently of extension ownership. Does not touch volume. No scheduling runs in the service worker.
- `src/integration/metadata.ts`: source-inspected endpoint and payload guards, current episode/version binding, resource selection and bounded cue loading. No authentication or alternate-version lookup.
- `src/integration/caption-display.ts`: literal player-label/CC-role association with one current resource, whitespace-only cue-to-DOM offset projection, and text-node redaction preserving real line breaks. English-looking dialogue never decides language. Ambiguous locales, roles/resources and unknown labels fail closed.
- `src/integration/katamari.ts`: capability-gated Bitmovin caption overlay adapter based on user-supplied markup and source-inspected track-menu semantics. Reads the checked subtitle radio in `audio-text-track-menu`, requires unique current-version metadata and exact cue agreement, then changes only caption text nodes in the mutation microtask before browser paint. Originals and native inline elements/styles remain in place; there is no duplicate renderer or hidden original caption layer. Requests a fresh automatic menu read each session; another resource request invalidates selection and requires another read, never treating prefetch as selection. Nodes are bounded to 512/32,000 characters and pruned when removed. Verification can survive a replacement layer for the same current track, but never an episode/track reset. A short visible redraw mismatch has a 250 ms pending interval; persistent mismatches and absent expected cues still report unavailable. Text-action logs require actual visible cue replacement.
- `src/integration/track-menu.ts`: bounded automatic read of the source-identified native menu. Calls only its toggle button, reads the checked subtitle radio, and closes only a menu it opened. Its temporary popup/wrapper is concealed before paint, with original inline styles restored on success, cancellation, failure or teardown. A two-second read limit and 500 ms close limit prevent an invisible stuck menu. Actual pointer/keyboard input cancels the read. User-opened or other expanded controls are left alone; no radio is selected and no prior episode's language is reused. No playback, volume, mute or autoplay control is called.
- `src/integration/coverage.ts`: player notice presentation, separate from filtering. Popup status remains immediate. In-player loading notices wait for 1.5 seconds of continuous loading, while unavailable/error reasons (including missing dub CC) remain immediate. Changing a loading message does not restart the delay. Only the two coverage slots are read from a full snapshot; null metadata is not treated as a status.
- `src/integration/crunchyroll.ts`: MAIN-world, document-start coordinator. Observes only page-initiated fetches, preloads resulting English text resources, gates the documented SubtitlesOctopus API and feeds the guarded Bitmovin adapter. A single document mutation observer handles caption changes and checked menu metadata before paint. Uses native renderer output; adds no duplicate subtitle layer. Unknown paths stay unavailable. A fresh media timeline is required before audio arms.
- `src/content.ts`: ISOLATED-world, document-start bridge. Validates bounded snapshots, registers its actual frame/document, passes settings and forwards narrow player commands. No privileged fetch or execution bridge.
- `src/background.ts`: synchronous MV3 message registration; serial settings writes and routing using actual sender tab/frame/document identity. `storage.session` holds only bounded routing descriptors. Popup reads get a live probe from the exact document. Stale requests fail rather than falling back to another player/tab.
- `src/popup.ts`, `src/options.ts`: native accessible HTML/CSS. Text is rendered with `textContent`; term editor values never become HTML. All contexts use the same persisted mutation path. Options revisions reject stale drafts.

## Data flow

Page-initiated current-version metadata → local English resource read (ordinary CORS, no credentials) → parser/originals in frame memory → matcher and SHA-256 occurrence identities → ASS source before renderer construction/track selection, or verified Bitmovin caption text before browser paint, plus the media-time cue scheduler.

The known top/player origins relay metadata directly between their MAIN worlds. This includes the exact caption URLs already returned to the page, solely in page memory so selected resources are compared accurately even when URLs differ only by query parameters. URLs never enter popup reports, extension storage, application logs or the privileged bridge. This channel cannot initiate fetches or invoke extension APIs. Its input is revalidated and caption source is reparsed on receipt. A page can already control its own media; the correlation token on the isolated bridge is **not** claimed to authenticate against a hostile same-page script.

The isolated bridge accepts only snapshots and responses with the correct window/source/origin/channel/token and schema. Those messages cannot mutate settings, initiate requests or execute code. Only allowlisted packaged popup/options senders may mutate settings or route actions. The worker requires an active Crunchyroll watch tab and an exact registered frame/document/instance/episode/version. An Ignore ID must exist in that live snapshot and pass another frame handshake before persistence. Timestamp commands carry occurrence IDs, not arbitrary page navigation URLs.

Settings and exceptions: `chrome.storage.local['quietroll.v1']`, trusted contexts only. Existing scaffold data is preserved under its old key. Unsupported saved versions are reported rather than reset. All writes await storage and are serialized. The worker does not keep subtitles or occurrence logs.

## Permissions

The only API permission is `storage`. Explicit host access is limited to `https://www.crunchyroll.com/*` (SPA playback metadata, watch pages, tab identity and routing) and the known static Vilos player path (frame injection/routing). Chrome host permissions apply at origin granularity even when a path is declared. Content scripts run in matching frames in MAIN and ISOLATED worlds; there is no all-web access, tabs permission, scripting permission, microphone, tab capture, webRequest, remote code, web-accessible resource, general proxy or backend. Caption CDN fetches use the page's existing CORS permissions and do not add CDN host permissions. `extension.policy.json` is checked against the packaged manifest.

## Lifecycle

Playback requests invalidate prior cues immediately. Navigation, player replacement and source resets discard stale identities/intervals and restore only owned muting. Navigation is checked before page metadata requests as well as by the periodic fallback, so that fallback cannot invalidate an already prepared next episode. Known metadata preparation reports loading for at most seven seconds and never arms old cues. New media metadata arms a fresh timeline and permits a current-episode menu read. Seeks, paused/buffering states, playback rate and settings changes recompute from `currentTime`. Same-source server-inserted ads cannot currently be distinguished reliably from normal playback/seek: that remains an unsupported/unverified timeline path, not an asserted success.

Rules/Ignore updates regenerate from original caption text, never from already redacted text. English CC audio timing is independent of the visible subtitle choice when the data can be obtained. Non-English renderer inputs are untouched. Disable/track change restores through the ASS renderer API or restores only extension-owned text-node edits. Host text changes supersede retained originals. No guessed CSS selector hides a caption canvas. Video-element-only fullscreen cannot hold an HTML coverage badge; player-container fullscreen retains the actual caption layer and is the supported fixture path.

## Timestamp navigation correction — November 13, 2026

Version 0.1.0 wrote `video.currentTime` directly. The user's live report established that the clock moved but the site's Play/video controls did not resume until the native timeline was used. That is consistent with bypassing a stateful player seek path; this environment cannot independently reproduce the exact live player.

The public [CrOptix Katamari integration source](https://github.com/stratumadev/croptix/blob/main/src/utils/katamari.js), inspected via the GitHub connector, includes Crunchyroll's `BrowserMediaSessionHandler`: it registers `navigator.mediaSession.setActionHandler('seekto', ...)` and forwards `seekTime` to the player handle's `seek` method. Only this observed contract informed the correction; no downloaded script, webpack rewriting, authentication, stream access or private-object probing was added. The [standard setActionHandler contract](https://developer.mozilla.org/en-US/docs/Web/API/MediaSession/setActionHandler) and [native seek completion event](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/seeked_event) were checked.

Version 0.1.1 captures that registration in the MAIN world, retains its native registration and calls the site's original callback. A media-time completion check observes real native events; it does not dispatch fake `seeking`/`seeked` events, call `load`, or force playback. Pending requests cancel on media/episode replacement or a superseding timestamp. The handler is bound to a single media element; a stale handler cannot be reused on a replacement video. Absent Media Session registration uses native-media fallback. A disabled/rejected SDK action is never bypassed by that fallback.

This fixes the source-identified bypass and passes a stateful-player regression model. The live Crunchyroll registration/exact behavior and server-inserted ad timeline remain unverified. Subtitle renderer coverage is unchanged by this revision.

## 0.1.7 preferences sync and backup

`core/backup.ts` validates a bounded versioned settings-only JSON format. `shared/settings-sync.ts` serializes UI edits and remote application around the existing durable local repository; remote preferences never replace local occurrence exceptions. Worker listeners are still registered synchronously. Both local and sync areas use TRUSTED_CONTEXTS; only trusted UI pages can request sync/backup operations. Current preferences are sent to active frames on remote application. Stale form revisions are rejected, leaving draft edits intact.

Chrome Sync stores canonical preference JSON in content-addressed 1,000-UTF-16-unit chunks and a final schema/hash/count manifest. A complete validated generation applies as one preference revision. Missing or corrupted chunks cannot replace local settings. A 44 KB profile budget reserves space for the current and next generation under Chrome's 100 KB total/8 KB item limits; custom terms retain their independent local 250×100-character bound. Obsolete keys in this namespace are pruned when staging another generation. Local pending/hash/conflict metadata survives worker suspension. Native offline transport is Chrome's responsibility; local size/native write errors remain visible and retryable. A fresh install waits for a received profile rather than uploading untouched defaults. Existing local preferences conflict with a different received profile until the user chooses. Normal complete remote updates apply when no local edit is pending; simultaneous/offline divergent profiles require an explicit choice, not field-level merging.

Sync is controlled locally per device. Clear disables it here before removing this namespace's keys; other enabled devices can republish after edits. No alarms, background process, login/OAuth, credentials or extra host/API permission is added. The standard release gate remains required; `scripts/package-store.mjs` then copies the tested ZIP and actual settings screenshots into a separate store submission kit. Store publication is performed by the publisher, not by this script.

## 0.1.8 exact-text subtitle association

The user-supplied inline LI with pre-line whitespace establishes that the reported subtitle is DOM text, consistent with the guarded overlay hierarchy. A mismatch status establishes a failed cue association, not hardcoded pixels. `DisplayCueIndex` first projects exact current cues, then looks up one complete, whitespace-normalized displayed cue in the selected track. Multiple identical cue identities without unique current timing remain unavailable; differing wording and unsupported overlapping combinations are not approximated. Index lifetime is the renderer/track lifetime; session and track invalidation still release originals and discard it.

The fallback retains source cue/match IDs, so Ignore and immediate rule changes cannot be transferred to unrelated dialogue. `FilterEngine` records DOM text actions against the renderer's actually changed cues even outside their source intervals; pre-render ASS continues to use media time. Audio scheduling and timestamp navigation never use this fallback or acquire inferred offsets. The active subtitle reason reports when display/source timing differ and asks the user to check audio synchronization. That mode establishes text replacement only, not accurate audio timing. Native nodes, styles, line breaks and restoration behavior are preserved; no extra renderer is created.

After a unique cue demonstrates timing drift, repeated lines cannot use the unverified media clock to select an occurrence. A unique aligned cue must re-establish timing first. This guard survives replacement of the same track's overlay and resets with the track/session.

## 0.1.9 explicit episode timing correction

`FilterEngine` keeps a bounded, validated ±300-second manual offset per current English-dub CC track in player memory. It adds this offset to prefetched whole-cue intervals and timestamp navigation, retaining original cue keys, raw times and exceptions. Popup snapshots separate raw source time from corrected playback time. Changing the offset clears prior audio-action claims, rebuilds merged scheduling and releases only extension-owned muting. The same offset informs overlay cue association, without retiming native subtitles. Settings, storage, sync schemas and permissions are unchanged; episode/session invalidation clears the correction.

The trusted popup routes the correction through existing tab/frame/document/session checks; the worker checks the current CC identity, then the engine validates the current language, version, timeline, track and finite offset again. No page fetch/execution facility is added. Unknown/unsupported languages, Japanese audio and missing matching CC cannot gain audio coverage from an offset.

`CaptionTimingGuard` is negative evidence only. A unique exact cue continuously displayed outside its adjusted interval for at least 500 ms of advancing playback (with a bounded redraw tolerance) can block that track's audio and links and clear unreliable audio-action logs. It never infers an offset or enables audio. Pause, seeks, buffering, discontinuities, cue gaps, ambiguous text and hidden layers reset observation. This does not verify every cue or audio track, and cannot detect mismatches when no usable subtitle evidence exists. A manually verified correction can recover the schedule; another sustained mismatch blocks it again.

## 0.1.12 recovery lifecycle

`shared/recovery.ts` implements retryable, single-flight worker initialization and bounded content-frame registration (timeout plus backoff). A successful registration leaves no heartbeat. Newer saved-state revisions cannot be overwritten by a slower registration response; page messages do not initiate privileged requests. Synchronous worker listeners and the Chrome 120-compatible `sendResponse`/literal `true` contract remain unchanged.

`integration/caption-loader.ts` owns up to six already-observed English resources for the current metadata generation. It reuses successful reads, retries network/timeout/429/5xx failures after 0.5/1.5/4 seconds, and stops on navigation, source invalidation or pagehide. Other HTTP failures, oversize bodies and malformed caption files are not automatically retried. Explicit Refresh player retries failed downloads. No speculative metadata/auth requests, new origins, logs or persistent transcript cache are introduced.

The adapter reads native `readyState` on attachment so an earlier `loadedmetadata` event is not required twice. A video replacement during a fresh request retains that request's generation; ambiguous media still invalidates it. Metadata-only readiness recovery requires the same episode, version, audio locale, ordered track IDs, original documents, timeline metadata, video object, source and media-event revision. The delayed check lets the site's fetch continuation initiate a normal reload first. Only that verified unchanged binding can restore an ASS renderer and session-local timing controls; an unexplained source reset still discards timings.

Persisted pagehide releases owned muting, restores captions and disconnects observers. Pageshow reconnects only a completed verified same-source session, recreates media controls/observers and re-registers the document. A changed/incomplete binding stays unavailable pending fresh metadata. This does not force BFCache eligibility or bypass DRM. Subtitle-menu probes make at most three attempts with backoff per reset, restore focus/styles, and stop automatic reopening after trusted user interruption.

Official contracts checked: [worker lifecycle](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle), [messaging](https://developer.chrome.com/docs/extensions/develop/concepts/messaging), [content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts), [native readyState](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/readyState), and [pageshow](https://developer.mozilla.org/en-US/docs/Web/API/Window/pageshow_event). Normal worker suspension must not own precision playback scheduling.
